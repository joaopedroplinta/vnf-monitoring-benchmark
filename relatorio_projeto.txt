OBJETIVO
--------
Projeto de TCC que compara 3 abordagens de monitoramento de rede aplicadas a
uma VNF (Web Application Firewall):
  - eBPF (BCC):       instrumentação em nível de kernel via kprobes
  - Sysstat (psutil): polling tradicional em userspace via /proc
  - Prometheus:       stack moderna com scraping HTTP

COMPONENTES IMPLEMENTADOS
--------------------------

1. VNF — Web Application Firewall (src/vnf/)
   - waf.py (153 linhas): TCP server na porta 8080
     * Detecta: SQLi, XSS, Path Traversal, RCE, Null Byte
     * Rastreia métricas por conexão (bytes RX/TX, blocked/allowed)
     * Simula carga de CPU com loops matemáticos intencionais
     * Exporta métricas para vnf_metrics.json periodicamente
   - monitor_server.py (42 linhas): UDP server na porta 9999
     * Responde a qualquer requisição UDP com métricas do WAF em JSON
     * Ponto central de telemetria para todos os coletores

2. Coletores (src/)

   eBPF (monitor_bcc.py — v23, 171 linhas):
   - Kprobes em tcp_sendmsg e tcp_cleanup_rbuf
   - Filtra sport == 8080 para evitar dupla contagem no loopback
   - Latência medida via UDP RTT em userspace
   - 1 amostra/segundo por 60 segundos
   - Saída: results/ebpf_results.json

   Sysstat (collector.py — v2, 134 linhas):
   - Lê /proc/net/dev na interface loopback
   - Consultas UDP ao monitor server para métricas do WAF
   - Latência como RTT UDP usando time.time_ns()
   - Saída: results/sysstat_results.json

   Prometheus (exporter.py — v2, 144 linhas):
   - Métricas exportadas:
     * monitor_latency_ms (Gauge)
     * monitor_latency_histogram_ms (Histogram)
     * waf_connections_total, waf_bytes_rx_total, waf_bytes_tx_total
     * waf_cpu_percent, waf_mem_mb
     * waf_blocked_total, waf_allowed_total
   - Saída: results/prometheus_results.json

3. Geração de Tráfego (src/client/)
   - client.py (83 linhas): envia 200 mensagens TCP com intervalo de 1s
   - gen_payload.py (75 linhas): gera payload.bin de 2MB com:
     * 60% conteúdo limpo (texto, números, pontuação aleatórios)
     * 40% padrões maliciosos:
       - 5 variantes SQLi (UNION, DROP, INSERT...)
       - 4 variantes XSS (script, onerror, javascript...)
       - 4 variantes RCE (bash, wget, cmd, curl...)
       - 4 variantes Path Traversal (../, variantes encoded)
       - Padrões de Null Byte
     * Payload reutilizado em todos os testes para consistência

4. Comparação (src/compare.py — 80 linhas)
   - Consolida saídas dos 3 coletores
   - Compara 13 métricas-chave
   - Gera results/comparison.csv e results/comparison.json


INFRAESTRUTURA DOCKER
----------------------
- docker-compose.yml:   orquestra WAF + Monitor + Client + 3 coletores + Comparador
  * Comparador aguarda 480s (8min) antes de rodar compare.py
  * Volume compartilhado results_vol para persistência dos resultados
- docker-compose.{ebpf,prometheus,sysstat}.yml: stacks isoladas por coletor

Configurações relevantes:
  - network_mode: host (para monitorar interface loopback)
  - eBPF: privileged: true, pid: host (acesso ao kernel)
  - Bind mounts: /sys/kernel/debug, /sys/fs/bpf, /lib/modules, /usr/src
